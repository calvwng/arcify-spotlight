# Little Arc header and lifecycle

This local paired candidate builds on the header-flow pair. It is not a new repository commit and does not change permissions, website access, pairing, direct-mode opt-in, or transfer authority.

The compact tinted strip shows the hostname derived from the checked native tab. **Open in [Space]** executes the existing protected direct flow when enabled; **Review for [Space]** opens trusted confirmation when direct mode is off. The separate chevron opens a searchable Space list. Typing, arrow keys, Enter on a result, or choosing a Space changes only the proposed destination. It never transfers the page. Escape closes the chooser and returns focus. More contains window selection, refresh, trusted controls, and window-size settings. Critical errors remain visible.

Space colors use validated six-digit colors when supplied, with a stable decorative color fallback. Window labels remain stable within a header instance; native numeric IDs are not displayed. Exact window/Space/folder identity remains authoritative even when names change. Missing or changed explicit destinations are rejected without substituting another destination.

Ordinary tab completion is now a readiness hint. It does not disconnect or remount a healthy header, replace the selected destination, or reset a pending operation. Genuine loading/navigation, source identity changes, pairing changes, and disconnects retain their invalidation paths. A successfully authenticated binding replenishes the bounded reconnect allowance; failed bindings still have bounded retries. The dispatch ledger continues blocking uncertain outcomes across reconnects.

Shift-click reports an explicit page-reload instruction when an API throws **Extension context invalidated**. Other connection failures retain retry/fallback feedback. Nothing is opened or replayed by that message. Historical stale-content-script causation in the user's original report remains an inference: a disposable native extension reload was refused with `unsupportedDeveloperExtension`, so the invalidation/error distinction is covered synthetically. No re-enable or browser restriction bypass is part of this candidate.

Native acceptance uses disposable profiles and synthetic pages. Same-tab identity, JavaScript state, form value, history length, focus, exact membership, repeated-click protection, delayed-resource completion, navigation retirement and stale destinations are checked. Full browser restart, forced interruption at every transaction boundary, BFCache/prerender, hostile page presentation, media continuity and physical multi-monitor/mixed-DPI behavior remain separate acceptance gaps. The page-hosted header retains the explicitly accepted clickjacking tradeoff; extension-origin presentation is not browser chrome.

See [destination theme and chooser dismissal](little-arc-destination-theme.md) for the follow-up presentation behavior and boundaries.
