# Optional source-page dimming

Open **More → Little Arc settings → Source page dimming** in Little Arc. Enable dimming and choose a darkness percentage, then Save. The controller's sample preview is illustrative; editing it does not revive a real source-page lease. Cancel discards the draft. Dimming remains off by default, and an existing enabled setting is preserved. It applies only to successfully acknowledged Shift-click/Peek → Little Arc launches. Context-menu, Spotlight search, and other opening routes are unchanged.

Darkness is an integer percentage from 15 to 100. If no strength has been saved, the darker default is 55% (previously the fixed shade was 28%). The rendered black overlay uses that percentage as its alpha; 70% is darker than 55%; 100% is fully opaque black until source interaction or focus clears the decoration. Existing explicit strength values are preserved. Malformed saved data fails closed and is reported without silently replacing it.

Spotlight remains the single storage authority: `littleArcDimSource` is the existing enabled boolean and `littleArcDimStrength` is the new integer percentage. Reading missing preferences does not write storage. The trusted Arcify controller proxies paired background requests; Spotlight serializes compare-and-set with full expected enabled/strength values and verifies readback. Immediately before a changed write, Spotlight requires a bounded, one-use callback proving Arcify still owns the exact pending request and controller. Timeout, changed pairing, expired controller or stale settings fail closed without retry. Cross-extension/native operations cannot provide an atomic transaction across the final proof and storage dispatch; a write already sent is not rolled back on a lost reply.

The old editable Spotlight options toggle is replaced by directions to Little Arc settings. Older Arcify builds can still open the existing settings route, but need an update for the new controls. Older Spotlight builds do not support the preferences endpoint; the trusted controls must report unavailable rather than creating a second settings copy. Settings changes retire existing cosmetic leases; the next successful launch uses the saved strength.

Only the verified source document is dimmed. The overlay is decorative, static, hidden from assistive technology, and ignores pointer input. It does not change page focus, keyboard navigation, accessibility state, or browser focus. Static rendering also respects reduced-motion preferences without an animation.

Returning to the source, interacting with it, switching focus away from the Little Arc window, closing either associated window/tab, navigation/loading in either associated tab, changing pairing/settings, or losing the cosmetic connection ends dimming for that launch. It does not automatically reappear when refocusing Little Arc. The conservative loading cleanup can also end dimming when a subframe starts loading. This affects appearance only. A new successful launch can start a new dim.

A dedicated cosmetic connection renews a four-second lease, with a ten-minute absolute cap. Worker suspension, invalidated extension context, disconnection, or stalled communication fails to an undimmed page. Unsupported pages and unavailable receivers simply skip dimming. No new permissions are requested.

The cosmetic state retains only source tab/window/URL/document identity, confirmed destination tab/window identity, pairing generation, and a random cosmetic lease identifier. It carries no launch connection, operation, placement authorization, or replayable action. Exact documentId and frame-zero messaging and browser-owned sender metadata constrain the isolated receiver. Multiple source pages have independent leases; a replacement lease cannot be cleared by callbacks from its predecessor.

Native multi-window focus behavior and source-page appearance require later manual browser acceptance. Unit tests do not prove operating-system focus delivery timing.

Switching the active tab in Little Arc also ends dimming, including switching to its trusted window-size controls. The cosmetic association does not discover or grant authority to additional controller tabs.

Little Arc settings reads a fresh controller view immediately before opening. This avoids using the header's cached two-minute view after it expires, without retrying a possibly dispatched settings action. Explicit Space and destination choices remain unchanged; placement uncertainty remains locked. A confirmed successful settings open permits another deliberate open after Refresh choices. An uncertain reply never automatically reopens settings.

If the known ready controller tab is closed, inspecting or returning to the temporary page refreshes choices without creating a tab. A subsequent explicit Little Arc settings click may recover that exact missing controller in its existing window. Recovery uses one bounded transaction with current-document proofs before creation and before committing the new controller; it never replays a lost response or a placement. Returning to the source after a confirmed settings open refreshes choices automatically. Uncertain settings outcomes remain blocked.

The paired background sends a versioned, generation-bound closure notice only after recording the exact controller's native removal proof. The notice refreshes the matching active source document's choices without creating a tab, including when activation arrived before removal or an earlier read was still pending. Uncertain dispatched actions remain locked.
