# Shift-click Little Arc and optional Peek

Shift-click link opening is opt-in and off by default. Pair Arcify and Spotlight, then enable **Shift-click links / Open Shift-clicked web links in Little Arc** in Spotlight options. A trusted Shift + primary click opens one real page through the existing Little Arc temporary-window flow, with no iframe and no automatic Space placement. Its existing header can place that same native page in a selected Space. Existing `peekEnabled: true` users keep their opt-in but now get Little Arc; absent/false remains off. The separate `peekIframeEnabled` setting defaults false. Enable **Use iframe Peek instead (experimental)** to restore the optional preview described below. Changing either setting invalidates pending and active source sessions.

Only ordinary HTTP(S) anchors in the main webpage are covered. Plain clicks, other modifiers, downloads, editable controls, named-frame links, child frames and extension pages retain their existing handling. Sidebar Shift selection is unaffected. A page's earlier window-capture handler can prevent the extension from seeing the event. Existing pages may need reloading after extension updates; no content-script sweep is performed. Before the local opt-in has been read, native handling remains unchanged. Use the existing Little Arc link context menu where interception is unavailable. Pinned/Favorite source pages are supported without moving or unpinning them; transient, private and non-normal source windows are rejected.

Once opt-in is known, an eligible click prevents native Shift-click immediately, including during a cold connection. Visible connecting feedback holds one immutable link intent for at most 2.5 seconds. Readiness can continue that single gesture only while the source URL, connected link URL/eligibility, mode and focused visible document remain valid. Focus loss, timeout, navigation, disconnection, settings changes and link replacement cancel it without opening. The intent is cleared before dispatch. Initial handshake failure can recover on a later genuine pointer/focus/Shift-click even if readiness has never succeeded. Recovery is read-only until a fresh trusted gesture; no native action is retried. Unavailable feedback explicitly says when no action was sent. A dispatched uncertain action retains the existing durable receipt guard and recovery instructions.

The optional Peek modal always provides **Open in Little Arc**, even if the iframe is blocked, blank, redirecting, or requires sign-in. **Open in current Space** is next to **Close Peek**. Both actions open the verified current preview URL anew. If it cannot be established, the address explicitly says **Original link — current preview URL unavailable**, and the original link is used. A failed fresh probe of a previously bound document fails closed rather than silently using a stale URL. Forms, JavaScript state, history, scroll and sign-in state are not transferred. Expansion may briefly show a Little Arc window while the backend creates and commits the same web tab into the originating window's current Space. Closing during an action cannot undo a native operation already sent.

An extension-owned wrapper isolates the preview address and contains the website in an opaque-origin sandbox (`allow-scripts allow-forms`). It does not grant the website same-origin access, remove third-party restrictions, or guarantee authenticated browsing. CSP/X-Frame-Options still apply across the full ancestor chain, including the outer webpage. Use Little Arc when embedding is blocked or unsuitable. No security headers, API permissions or host permissions are changed. A second, small static HTTP(S) content script runs in frames under the existing site access; it is inert unless its immediate ancestor is this extension. A webpage can still cover or interfere with the overall embedded interface or attempt clickjacking.

An uncertain action disables both opening buttons. Inspect existing Little Arc controls and native windows. A backend browser-session receipt retains the original link and selected destination URL; it blocks reopening the same source/link after a lost response or worker restart. Existing v1 receipts retain their suppression semantics. If opening was confirmed but acknowledgement cleanup failed, the UI explicitly says the selected page already opened.

`shared/peek-content.js` owns the closed shadow modal and trusted opening gestures. `peek-wrapper.html` / `shared/peek-wrapper.js` own the read-only preview address and opaque child. `shared/peek-preview-broker.js` binds exact runtime Ports using single-use challenges sent only to the extension wrapper at its exact origin. The top script challenges its stored wrapper WindowProxy; the isolated child observer challenges only its immediate extension parent. The wrapper checks the exact stored child's WindowProxy and replies privately. Matching URLs, a web-accessible wrapper URL, frame indexes, page claims and nested frames provide no authority. Challenges never appear in DOM, URLs, wildcard messages or messages delivered to web content. The wrapper has no opening authority.

The isolated observer reads its own location after its own load, watches hash/popstate and polls at 250 ms only while bound. Fresh action-time and backend guard samples cover History API changes without patching page JavaScript; browser restrictions on History operations in opaque origins still apply. Redirects and full navigation require a fresh document/Port binding. Optional browser document IDs are used when supplied; otherwise a fresh private Port plus per-binding revision and direct-child proof are mandatory. Old document events, pagehide/BFCache suspension and disconnect retire the old binding. Load events conservatively invalidate tracking; they never open a native page. An in-flight navigation can therefore interrupt an action safely.

Preview frames receive no parent URL referrer. Only an open idle preview sends read-only 15-second backend heartbeats, without extending its 30-minute lifetime. Idle worker capability can warm on a real pointer/focus gesture; interrupted existing operations never rearm. Version 3 capability negotiation rejects mixed old/new pairs before any native opening.

See Arcify `docs/peek-prototype.md` for transaction, receipt, recovery and testing contracts. Focused Spotlight tests: `node node_modules/vitest/vitest.mjs run test/unit/peek.test.js test/unit/peek-preview.test.js --maxWorkers=2 --configLoader native`.

Primary references: [isolated content scripts and frame matching](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [programmatic injection requires host access or activeTab](https://developer.chrome.com/docs/extensions/reference/api/scripting), [webNavigation requires a new permission, which this implementation does not request](https://developer.chrome.com/docs/extensions/reference/api/webNavigation), and [extension storage/cookie partitioning has specific exemptions rather than a universal wrapper exemption](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies).
